# Система работы с задачами

Один файл — `pipeline.html`. Откройте его двойным кликом в любом браузере
(работает и на телефоне). Ничего скачивать или устанавливать не нужно —
страница самодостаточна: ни одного внешнего адреса, шрифта или скрипта,
всё уже внутри файла.

## Что внутри

Связное описание системы работы: 19 разделов с оглавлением наверху
(каждая ссылка ведёт на свой раздел), от того, как задача превращается
в тикет, до того, как она не теряется на любом из следующих шагов —
приёмка, архив, сторожа, каналы сигналов, память, уборка, секреты,
экономия, отчётность, связка трекера со средой разработки. В основе —
путь одной задачи из семи шагов (с
пометкой, где нужен человек, а где справляется механизм) и восемь кусков
кода на bash, которые копируются по кнопке прямо со страницы: шаблон
тикета, подъём работы по номеру задачи, простой сторож, протокол приёмки,
gate перед пушем в защищённую ветку, шаблон чекпойнта, сверка «бой ↔
архив» и опись перед удалением ветки/копии.

## Как подключить код у себя

Каждый скрипт настраивается переменными окружения — в самом скрипте
написано, какими. Например, для `newwork.sh` достаточно одной команды,
которая по номеру задачи печатает её текст:

```bash
export TRACKER_FETCH="gh issue view"   # если задачи — в GitHub Issues
./newwork.sh 42
```

Если трекера нет вовсе — годится даже один markdown-файл со списком задач;
про это отдельно в разделе «Тикет — единственный список задач» страницы.
